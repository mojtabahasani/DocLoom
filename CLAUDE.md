# دیتاسیو (datasave.ir) — سابقاً DataSave Pro

## داروین
این پروژه یکی از قطعات داروین است (`~/MyApp/darwinapp`). قاعده‌های آن اینجا هم جاری‌اند:
- **اول کاتالوگ، بعد کد** (ADR 0005): پیش از ساختن هر زیرساختی، `node tools/catalog.mjs --find X` در داروین. نبود → اول آنجا.
- **قانون جهت `DW-RTLNAV`** (ADR 0004 §۸) — پایین‌تر در همین فایل، با تست.
- **قرارداد زبان بصری** (ADR 0008): انتخاب پروژه در `.darwin/style.json`. قالب‌های رنگیِ **سند** از پالت‌های داروین می‌آیند؛ **پوستهٔ خودِ برنامه** هنوز پالت سبز برند است و از ۱۴ رنگ قرارداد پیروی نمی‌کند — **استثنای داروین: پوستهٔ برنامه — دلیل: مالک همین پالت را می‌خواهد و مهاجرت کل ظاهر را عوض می‌کند — بازبینی: ۱ اسفند ۱۴۰۵**.
- **ثبت در رجیستری** (ADR 0004 §۴): `darwinapp/registry/projects/datasave.json`. هر بار پورت، سرور، بکاپ یا قاعده‌ای عوض شد، همان جلسه آنجا هم به‌روز شود.
- **نگهبان کد** (ADR 0003): نصب شده. موتور `@darwin/guardian@0.3.2` از `vendor/darwin/*.tgz` (devDependency، بی‌وابستگی). پیکربندی: `scripts/guardian/config.mjs` — پنج قاعده از بستهٔ مشترک داروین با `extends` (`DW-RTLNAV→MD-RTL`، `DW-COLOR→MD-HEX`، `DW-DIGITS→MD-DIGITS`، `DW-DIALOG→MD-DIALOG`، `DW-SECRET→MD-SECRET`، هر `override` با `reason`) به‌علاوهٔ دو قاعدهٔ همین پروژه: `MD-ACC` (آکاردئون در پنل برنگردد) و `MD-MOVE` (یک چکِ کل‌فایل: هر `data-move="X"` باید `id="X"` در `<template id="movedFromToolbar">` داشته باشد — همان باگی که برنامه را بی‌صدا در startup کشت). هوک `PostToolUse` در `.claude/settings.json` ثبت شده (با تأیید مجتبی، ۲۷ آبان ۱۴۰۵).
  - `npm run guard` گزارش کامل · `npm run guard:ratchet` دروازه (فقط نقضِ **تازه**؛ باید ۰ بماند) · `npm run guard:baseline` فقط وقتی عمداً چیزی grandfather می‌شود.
  - baseline: `scripts/guardian/baseline.json` — ۴۵ نقضِ توصیه‌ایِ موجود (بیشترشان رنگ ثابت در کد خروجی‌گیر) grandfather شده‌اند. critical هرگز baseline نمی‌شود.
  - استثنای موردی با `guardian-ignore <CODE>` **و یک جمله دلیل** در خود فایل، نه با پهن‌کردن regex (نمونه: `src/js/ui/fuzzy.js`).
  - آنچه عمداً قاعدهٔ نگهبان **نشد**، چون جای دیگری اجرا می‌شود: نابودنشدن داده (`tests/no-destroy.test.mjs`)، کنتراست و WCAG 2.5.3 (`tests/e2e/a11y.spec.mjs`)، یکی‌بودن قالب‌ها با CSS (`tests/doc-themes.test.mjs`)، پر شدن نوار پیشرفت از چپ (`tests/e2e/rtl.spec.mjs`).
- **نام (۲۷ آبان ۱۴۰۵): برنامه از `MD2Html` به «دیتاسیو» / `DataSave` تغییر نام داد — همه‌جا.** پوشه، ریپوی گیت (`mojtabahasani/DataSave`)، خروجی `DataSave.html`، پکیج `datasave`، CLI `datasave`، `DATASAVE_*`، `~/Documents/DataSave`، `window.DataSave`، هدر `X-DataSave`، قالب بکاپ `datasave-backup`، کلیدهای `datasave.*` و برچسب LaunchAgent `ir.computer123.datasave`.
  - **قاعده: تغییر نام نباید برای کسی یک سند، یک ترجیح یا یک فایل پشتیبان آب کند.** هر جا نام، *نشانیِ* داده بود، نام تازه نوشته می‌شود و نام قدیم همچنان **خوانده** می‌شود: `core/naming.js` (کلیدهای localStorage)، `server/lib/env.js` (`DATASAVE_*` بعد `MD2HTML_*`، و پوشهٔ دادهٔ موجود هرگز رها نمی‌شود)، `security.js` (هر دو هدر)، `library/backup.js` و `server/lib/backup.js` (هر دو قالب و هر دو پیشوند نام فایل)، `embed-config.js` و `embed/embed.js` (`MD2HTML_EMBED`، `window.MD2Html` و رویداد `md2html:ready` برای میزبان‌های موجود). `tests/naming.test.mjs` و `tests/e2e/embed.spec.mjs` همین قول را نگه می‌دارند.
  - **دو چیز عمداً عوض نشد، چون نشانی‌اند نه برچسب:** نام پایگاه‌دادهٔ IndexedDB (`md2html` در `library/db.js` — IndexedDB rename ندارد و کپی‌کردن کل کتابخانه زیر سهمیه‌ای که همین حالا پر می‌شود، کتابخانهٔ آفلاین را خالی می‌کند) و صفت‌های `data-md2-furniture` / `data-md2-keep-digits` که داخل html سندهای ذخیره‌شده‌اند. دلیلشان در `core/naming.js` نوشته است.
  - در `server/lib/backup.js` با دو پیشوند، مرتب‌سازی **با تاریخِ داخل نام** انجام می‌شود نه با نام: الفبایی `datasave-` پیش از `md2html-` می‌آید و rotation بکاپ تازه را می‌انداخت.

- Source lives in `src/` (vanilla ES modules + CSS). `DataSave.html` and `dist/` are **build output**: never edit them directly. Run `npm run build` after changes (it rebuilds `dist/DataSave.html`, `dist/pwa/`, and copies to `./DataSave.html`). Only the root `DataSave.html` and `dist/pwa/` are tracked; `dist/DataSave.html` is gitignored (identical copy) and the server serves the root one.
- `AGENTS.md` is a symlink to this file: edit only `CLAUDE.md`.
- Version: `package.json` is the single source, plus `BUILD_ID` — an 8-char fingerprint of `src/`, `build.mjs` and `package.json` that `build.mjs` computes and «دربارهٔ برنامه» shows. The version stays `1.0.0` all day, so this is the only way to tell a freshly built file from an open tab or a service worker still serving the old shell; when a fix seems absent, compare it before debugging. `build.mjs` injects it (and the build date) through esbuild `define`; `core/version.js` reads them and falls back to `dev` when a module is imported from source. The server reads the same file. Record user-visible changes in `CHANGELOG.md`.
- Accessibility: `npm run test:e2e` includes `tests/e2e/a11y.spec.mjs` (axe, WCAG 2.1 A/AA). It neutralises `backdrop-filter` before scanning — axe cannot see through it and otherwise invents contrast failures. Keep it green: new colours must clear 4.5:1, and a control that shows its own text must not carry a different `aria-label` (WCAG 2.5.3).
- Tests: `npm test` (node:test, pure modules under `src/js/content`, `brand`, `export/docx.js`, etc.).
- Browser tests: `npm run test:e2e` (`@playwright/test`, specs in `tests/e2e/*.spec.mjs`, config `playwright.config.mjs`). Its `webServer` runs `npm run build` and `tests/e2e/static-server.mjs`, which serves the repo root with **no `/api/*`** so the app stays in offline mode. Two projects: `desktop` (all specs) and `mobile` (Pixel 5, `layout.spec.mjs` only). `npm run test:all` runs both suites. Palette commands run on `setTimeout(…, 0)` after the palette closes — always wait for the command's effect, never assume `runCommand` has already run it.
- Browser check by hand: serve with `python3 -m http.server` (Playwright MCP blocks `file:`).
- Design spec: `docs/superpowers/specs/2026-10-30-datasave-design.md`. Feature parity list: `docs/superpowers/plans/feature-inventory.md`. User guide: `docs/راهنما.md`.
- `docs/قالب-گزارش.md` is the prompt handed to outside models (ChatGPT / Gemini). Its two ```text blocks are asserted byte-equal to `src/js/content/report-prompt.js` by `tests/report-prompt.test.mjs`: edit the module, then the doc. The user-level skill `~/.claude/skills/datasave/` mirrors it.
- Bank-statement import: `src/js/bank/` — `sheet-read.js` (xlsx via fflate, SpreadsheetML, CSV, and binary `.xls` through `cfb.js` + `biff.js`: an OLE2 reader and a BIFF8 record reader, both written here, no library), `bank-table.js` (header found by scoring, columns matched by name, newest-first files reordered so the running balance holds), `kinds.js` (short label + colour group per transaction; POS vs internet card purchase is the distinction that matters), `statement-html.js` (the printed table), `bank-report.js` (filters, bank guess, monthly roll-up), `bank-ui.js`. Spreadsheets reach it through `registerSheetHandler` in `editor/files.js`. Samples the parser is checked against: `~/My-Drive-Mac/Documents/print-bank/` (read-only, outside the repo).
- `tools/verify-bank.mjs` (`npm run verify:bank -- <files>`) reconciles a real statement against the importer: every transaction present with the same date, time and amounts; the running balance unbroken; and the group totals printed, with a hard check that fees stay under 2% of all movement. Run it after touching `bank/` — a wrong *label* loses no data, so row-level checks pass while the report lies.
- The statement is **HTML, not Markdown** — Markdown cannot stack a date over its clock, set a 6.5px description column or colour a cell. Layout is fixed (رج · زمان · شرح عملیات · واریز · برداشت · مانده) with no column picker; styles in `styles/statement.css`, which `export/html.js` embeds so print and PDF match. Its classes are whitelisted in `content/sanitize.js`: add a class there before using it in the markup.
- Saba / FastReport import: `src/js/saba/` — `fp3.js` (the `.fp3` prepared-report XML: short names `m1`, `b1` index the template in `<sourcepages>`, numbered **globally** in document order), `fp3-table.js` (no table exists in FastReport, so columns are rebuilt from Left/Width geometry and headers matched by overlap), `saba-report.js`, `saba-ui.js`. Shares `core/xml.js` with the spreadsheet reader and `bank/normalize.js` for the Persian cleanup.
- `editor/files.js` keeps a list of importers (`registerSheetHandler`, `findImporter`); the bank and Saba importers register themselves in `app.js`.
- `tests/صبا/` holds the user's real Saba exports and is **gitignored**: real financial data, used to check the parser by hand, never committed.
- A document never copies its brand's images. The four base64 images (`mastheadImage`, `footerImage`, `signatureImage`, `stampImage` — `BRAND_IMAGE_KEYS` in `library/doc-model.js`, mirroring `IMAGE_FIELDS` in `brand/brand-model.js`, asserted equal by `tests/library.test.mjs`) are ~5 MB together. `captureDoc` drops the ones that equal the document's brand and lists them in `layout.brandImages`; `docToPatch(doc, brand)` fills them back. **Inheritance fills a gap, never overrules:** a record that carries the image itself keeps it, which is what makes `restoreVersion`'s layout merge safe. An overridden image, or a document with no brand, is stored as before. Every `docToPatch` caller must pass the brand — `brands.any(id)` (unlike `brands.get`, it finds archived brands, so archiving a brand cannot blank a document's letterhead); missing it in `server/render-mode.js` would strip the letterhead from every rendered PDF. Copying them into every document *and every version* is what grew one library to 215 MB; `tools/dedupe-library.mjs` shrinks data saved before this.
- Archive rule (spec `docs/superpowers/specs/2026-11-14-datasave-archive-design.md`): **no button destroys data.** «حذف» sets `archivedAt` on the document/brand (`library.list()` returns live ones only, `library.archived()` the rest); `LibraryStore.del` gzips the content into `library/_retired/` before the tombstone. `tests/no-destroy.test.mjs` lists every allowed destructive call with its reason — a new `db.del`/`rmSync` must be justified there.
- `1file-old/` is the user's backup of the original single-file app: read-only.
- The toolbar holds only ⌘K and «دریافت HTML»; everything else (brand, library, files, server, app theme, new document, the title field, the export menu) lives in a panel group. Its markup stays together in `<template id="movedFromToolbar">` and `src/js/ui/toolbar-move.js` drops each node into the `data-move="<id>"` slot that names it, **before any init runs** — a node inside a `<template>` is invisible to `document.querySelector`, so a module that binds by id would get null. Moving a control = moving one `data-move` slot. A dropdown moves by its `.menu-wrap` (which needs an id), never by its button alone, or the menu is left behind.
- Side panels: `src/js/ui/drawer.js` + `styles/drawer.css`. A panel's groups are declared **only** in `index.html` — `<section class="dgroup" data-group data-name data-short data-icon data-emoji data-hue>` — and every control worth calling a tool carries `data-tool="نامش"`. The drawer counts those, so a group's badge and the "what's inside" line under the header cannot drift from the markup; adding a group is a markup change and nothing else. Both side panels use `data-shape="rail"` (the vertical icon rail, ≥1101px only); a group that holds two separate jobs nests its own `<div class="drawer" data-shape="tabs" data-head="off">` instead of stacking accordions — **there are no `<details>` left in the panels, don't add one back**. Below the breakpoint every drawer falls back to the tab row. Call `reveal('#someControl')` instead of poking a panel open: it walks up every `.dgroup` the control sits in, so both levels open, then scrolls to it and flashes it. Tabs carry **no `aria-label`**: the accessible name comes from the content, so WCAG 2.5.3 cannot be broken by a label that disagrees with the text. Group hues are only an edge, a dot and a pale wash — never text — so a new group can't introduce a contrast failure. Tests: `tests/e2e/drawer.spec.mjs`.
- Document colour themes live **once**, in `src/js/export/theme.js` (`DOC_THEMES`): the panel swatches, the ⌘K commands, `BRAND_THEMES` and the settings whitelist all read it, and `styles/document.css` repeats the same values for the preview with `tests/doc-themes.test.mjs` asserting the two agree. Adding a theme is one line there plus one rule in `document.css`. Four of the nine come from Darwin's theme pack (`darwinapp/packages/style/themes`, `apps/style-lab/src/styles/themes.css`); «دفترچه» carries a `rule` colour and `ruleCSS()` paints its ruled lines into every export, so print, PDF and HTML match the preview.
- RTL rules: never mirror prev/next controls; progress bars, sliders and chart x-axes fill left→right. In the panel drawers that means the rail's Down = next and the RTL tab row's **Left** = next.

## Server (S1)
- `server/` is pure Node (no npm deps), port 7123 (`DATASAVE_PORT`), data in `~/Documents/DataSave/` (`DATASAVE_DATA`). Foreground: `npm run server`. Serves `dist/pwa/` directly (no restart after `npm run build`).
- Listens on `127.0.0.1` unless network access is on: `lan` in `config.json` (panel button, `datasave lan on|off`, Mac-only route `/api/server/lan`), overridden by `DATASAVE_LAN=1|0`. `lanEnabled()` in `server/index.js` is the one place that decides; toggling rebinds the live server. Security work is tracked in `docs/نقد-و-نقشه-راه.md`.
- `server/install.sh` / `uninstall.sh` (LaunchAgent + `datasave` CLI) are written but **must be run by the user**; never run them, `launchctl` or write to `~/Library` from an agent. Test with `install.sh --dry-run <plist>`.
- Client sync: `src/js/server/` (pure merge in `sync-core.js`); active only when `/api/health` answers same-origin; never fetches on `file://`.
- Sync conflicts: **a missing `base` is not an edit on both sides.** The base map is per-device bookkeeping in `localStorage` while the documents are in IndexedDB, so it can simply be gone (storage cleared, a failed quota write, a restored server, a second device's first sync). Reading that as "both changed" split every document into a «(تعارض)» copy — it turned one library into 60 duplicates of 80 documents, duplicates of duplicates included. So `decide()` returns `compare` instead of `conflict` when the base is unknown, and the runtime fetches the remote record and calls `sameDocContent(local, remote, brand)` first; only a real difference becomes a copy. The `brand` argument matters: one side may reference the brand's images while the other still carries them (a half-propagated dedupe), and without resolving both the comparison would invent the conflict it exists to prevent. Still open: moving the base map next to the documents so it cannot be lost on its own.
- Tests: `tests/server/*.test.mjs` (integration uses `DATASAVE_TEST=1` for the remote-address override header; never set it otherwise).

## Server (S2)
- Files: `server/lib/files.js` (+ `file-routes.js`): realpath-confined API `/api/files/*`, SSE `/api/watch?path=`, backups in `data/backups/files/`. Test roots via `DATASAVE_ROOTS` (colon-separated; default `~/MyApp ~/Documents ~/Desktop ~/Downloads`): **never write into the real roots when testing.** Writes go through `FileService.resolve({write:true})`, which refuses agent instruction files (`PROTECTED_NAMES` in `security.js`) and `DATASAVE_RO_ROOTS`; a new write path must use it too.
- Client: `src/js/server/linked.js` (linked docs, live reload, ⌘S), `files-ui.js` (drawer), `files-picker.js`, `files-export.js`. The `link` field ({path,etag,mtime,size,dirty}) lives on the document; seed brand id is `brand_computer123`.

## Server (S3)
- PDF/batch: `server/lib/pdf.js` (Chrome via `--remote-debugging-pipe` CDP, single-worker queue, 60s timeout; `DATASAVE_CHROME` override), `batch.js`, route `/render` (loopback or job token only; app boots in render mode, `src/js/server/render-mode.js`). Current-doc PDF posts the export HTML to `/api/pdf`.
- Shares: `server/lib/shares.js` (`data/shares/<22-char id>/`, public `/s/<id>`, CSP `connect-src 'none'`). Finder bundles are generated: edit `server/finder/build-workflows.mjs`, run it, never edit `.workflow` by hand; never install them (install.sh does, user-run). Service workers cache the shell: unregister when smoke-testing a rebuilt app.

## Embed mode
- Opt-in only: a host page defines `window.DATASAVE_EMBED = { host, digits: 'en'|'fa', upload, library, server, brand }` before the app's `<script>`. **Without the global nothing changes** (`embedConfig().active === false`, every capability on, Persian digits). Config: `src/js/core/embed-config.js` (a capability is off only on an explicit `false`; `digits` defaults to `'fa'`). API: `src/js/embed/embed.js`, wired last in `app.js`.
- `library:false` skips `initLibrary`/`initLibraryUI`/`library.start` (no reopen, no autosave) and hides library/versions/backup UI and palette entries. `server:false` skips the `/api/health` probe (`initSync` returns false) and the server modules, and hides files/server/direct-PDF/batch/share/destination UI. `upload:false` hides the zi2.ir panel and refuses `uploadPendingImage`. Hidden nodes carry `data-embed-hidden` (`src/styles/embed.css`). No PWA glue in embed mode.
- `window.DataSave.embed` (`ready`, `config`, `slot`, `load({markdown,title,subtitle,doc,html})`, `getMarkdown()`, `getHTML()`, `getDoc()`, `isDirty()`, `markClean()`, `on('dirty'|'save', fn)` → unsubscribe, `print()`, `applyBrand(obj)`), then `window` event `datasave:ready`. ⌘S fires `'save'` only (store event `embed:save`). Host brands live in memory (`brands.register`), never in IndexedDB.
- Digits: `src/js/core/digits.js` holds the active script; `toFaDigits`/`faPercent`, `formatJalali` default, chart `fmtNum`, cleanup defaults and the presentation runtime (`data-digits="en"`) follow it. With `digits:'en'` `src/js/embed/chrome-digits.js` (MutationObserver) turns chrome digits Latin, never inside `#preview`, `#source`, `#sourcePane`, the reader, textareas or `[data-md2-keep-digits]`. Parsing accepts Persian digits in every mode.
- Tests: `tests/embed.test.mjs`, `tests/e2e/embed.spec.mjs`. On Windows run the browser suite with `E2E_CHANNEL=msedge` (or `chrome`) instead of downloading Chromium.
