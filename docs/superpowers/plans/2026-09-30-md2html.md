# MD2Html Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build MD2Html as a polished, offline, standalone HTML tool that turns Markdown or plain text into editable Persian RTL documents and exports them as HTML, email-ready content, or print-to-PDF.

**Architecture:** Deliver one file at `MD2Html/MD2Html.html`. Keep CSS and JavaScript embedded, with JavaScript organized into focused IIFE modules (`MarkdownParser`, `DocumentModel`, `EditorUI`, `ThemeRenderer`, `ExportHTML`, `ExportEmail`, `PrintManager`, `ContentSecurity`). Maintain source text separately from the editable document preview; exports use the rendered document model.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, browser File API, Blob/object URLs, Clipboard API with a selectable fallback, and browser print CSS. No server, package manager, external font, network dependency, or runtime library.

## Global Constraints

- Settings may be explicitly imported/exported as JSON; settings JSON excludes document content and images.
- Do not add SQLite or persistent document storage.

- The final user-facing application is one file named `MD2Html.html`.
- The app opens directly from disk and makes no network requests.
- Persian is the UI language; document layout defaults to `lang="fa"` and `dir="rtl"`.
- User text is never classified as dialogue and is never rewritten.
- Suggested headings and decorative blocks are separate editable elements.
- Drafts stay in memory only; no persistent browser storage or uploads.
- Only `http:`, `https:`, and `mailto:` links are allowed.
- HTML output embeds CSS and selected images; editor code is excluded from exported documents.
- PDF output uses A4 browser print; the app does not embed a PDF-generation library.
- Email output uses simple markup and inline styles, with selectable-copy fallback when rich clipboard write is unavailable.
- Do not add automated tests or run test suites unless Mojtaba requests testing or verification.

## Interfaces

- `MarkdownParser.parse(sourceText) -> DocumentFragment`: parse supported Markdown into DOM nodes using safe text insertion.
- `ContentSecurity.safeLink(rawUrl) -> string | null`: return a normalized allowed URL or `null`.
- `DocumentModel`: holds `sourceText`, `title`, `subtitle`, `header`, `blocks`, `theme`, and `dirty` in memory. Exposes `loadSource(text)`, `addBlock(block)`, `replaceBlocks(fragment)`, `serializeDocument()`, and `markDirty()`.
- `ThemeRenderer.renderDocument(model, {email, print}) -> DocumentFragment`: create document content from the model and selected theme.
- `ExportHTML.build(model) -> string`: return a complete standalone document HTML string.
- `ExportEmail.build(model) -> {subject: string, html: string, text: string}`: produce email-safe rich HTML and readable plain text.
- `PrintManager.print(model) -> void`: open a print-ready document and call its browser print flow.
- `EditorUI`: connect controls and synchronize source edits, preview edits, and export buttons with `DocumentModel`.

- [ ] Build the header with MD2Html name, short Persian guidance, and a clear local-only/privacy note.
- [ ] Build a source panel with Markdown file picker, drop zone, paste/edit textarea, title and subtitle inputs.
- [ ] Build a toolbar with buttons for heading, card, quote, divider, image, and link; buttons have labels and keyboard focus styles.
- [ ] Build the preview panel as a semantic editable document region, plus font-size controls and select-all/copy-text controls.
- [ ] Build export controls for HTML, email, and A4/PDF, plus a Persian status/alert region.

The shell task also adds settings JSON controls. Import rejects unknown keys, wrong app/version, invalid values, and files above 32 KiB. The JSON never contains the document, its title, preview HTML, or image data. Create md2html-settings.example.json with valid defaults.

### Task 2: Parse Markdown and plain text safely

**Files:**
- Modify: `MD2Html/MD2Html.html`

**Interfaces:**
- Produces `MarkdownParser.parse(sourceText) -> DocumentFragment` and `ContentSecurity.safeLink(rawUrl) -> string | null`.
- Consumes the source textarea and returns only allowed semantic document elements.

- [ ] Implement line parsing for paragraphs, blank lines, headings `#` through `####`, ordered/unordered lists, blockquotes, fenced code, horizontal rules, and pipe tables.
- [ ] Implement inline parsing for bold, italic, inline code, and Markdown links without assigning unsanitized source to `innerHTML`.
- [ ] Create DOM elements and set user-provided text through `textContent`; add links only after `safeLink` validates the URL protocol.
- [ ] Treat raw HTML in Markdown as text; never activate `script`, event-handler attributes, embedded frames, or arbitrary style attributes.
- [ ] Preserve source text as entered and show ordinary text as paragraphs when it contains no Markdown syntax.
- [ ] Return an informative Persian empty/error message for empty or unsupported input rather than dropping content silently.

**Deliverable:** Markdown and plain-text input render as safe, structured RTL document blocks without speaker parsing or content rewriting.

### Task 3: Add file input and editable document model

**Files:**
- Modify: `MD2Html/MD2Html.html`

**Interfaces:**
- Produces `DocumentModel` with the methods defined above.
- `EditorUI` binds file selection/drop, source edits, and direct preview editing to model state.

- [ ] Read `.md`/`.markdown`/`.txt` files through `File.text()`; reject other extensions with a clear Persian message.
- [ ] Support drag-and-drop and paste into the source textarea, clearing previous state only after the new source has been read successfully.
- [ ] On source changes, parse into document blocks and refresh preview while keeping source text untouched.
- [ ] On direct preview edits, update the document blocks and mark the model dirty without attempting lossy Markdown reconstruction.
- [ ] Implement select-all and copy-text for rendered document text, using Clipboard API when available and selection fallback otherwise.
- [ ] Implement font-size increase/decrease with practical minimum and maximum bounds, preserving RTL layout.
- [ ] Keep all source and document state only in JavaScript memory.

**Deliverable:** users can load, paste, and edit content in source or preview, and copy/resize the visible document.

### Task 4: Add themes, document controls, images, and custom links

**Interfaces:**

- `DocumentModel.blocks` supports semantic paragraph, heading, quote, list, table, card, image, divider, and link-button nodes.

- [ ] Implement four named themes: navy formal, green classic, warm cream, and monochrome; store the choice in memory.
- [ ] Add heading/card/quote/divider insertion at the current preview selection or at document end when no selection exists.
- [ ] Add text/image masthead controls and preserve aspect ratio for masthead images.
- [ ] Read image files locally, accept supported raster MIME types, reject oversized files with a Persian size message, and store accepted image data URLs in memory.
- [ ] Insert inline images with alt text and responsive sizing; embed their data URLs in exported HTML.
- [ ] Add custom labeled links and validate them through `ContentSecurity.safeLink`; reject `javascript:`, `data:`, and unknown protocols.
- [ ] Keep labels/content editable and visually indicate whether a block is selected or inserted.

**Deliverable:** the document can be styled and enriched with reusable visual blocks and images without any upload.

### Task 5: Build standalone HTML export

**Files:**
- Modify: `MD2Html/MD2Html.html`

**Interfaces:**
- Produces `ExportHTML.build(model) -> string`.
- Consumes the current preview-edited document model and selected theme.

- [ ] Serialize the document as a complete `<!doctype html>` page with UTF-8, `lang="fa"`, `dir="rtl"`, title, inline CSS, and semantic document content.
- [ ] Include print styles and theme colors, but omit editor panels, controls, event handlers, and application JavaScript.
- [ ] Include selected image data URLs and only validated links.
- [ ] Download the generated page through a Blob URL with a safe filename derived from the document title; revoke the Blob URL after download.
- [ ] Keep HTML text serialization safe so document text cannot create executable tags or attributes.

**Deliverable:** the HTML export is self-contained and opens as a readable Persian document without network access or sidecar files.

### Task 6: Add email and A4 print/PDF exports

**Interfaces:**

- [ ] Build a simple email layout from tables/paragraphs supported by common clients and inline the essential color, spacing, font, and RTL styles.
- [ ] Convert document link buttons to ordinary validated anchors; remove editor-only controls and unsupported interactivity.
