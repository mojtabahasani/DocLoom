# MD2Html Pro — طراحی نسخهٔ حرفه‌ای

**وضعیت:** تأییدشده توسط مجتبی (۸ آبان ۱۴۰۵ / ۳۰ اکتبر ۲۰۲۶)
**پیشینه:** نسخهٔ تک‌فایلی فعلی در `1file-old/MD2Html.html` بکاپ شده است. سندهای قبلی (`2026-09-30-md2html-design.md`، `2026-10-01-md2html-editor-upgrade-design.md`، `2026-10-01-rich-web-paste-design.md`) همچنان معتبرند، مگر جایی که این سند صریحاً خلافش را می‌گوید.

## ۱. هدف

MD2Html ابزار روزمرهٔ مجتبی برای چهار کار است:
۱) تبدیل خروجی هوش مصنوعی به سند فارسی تمیز
۲) نامه و سند رسمی با سربرگ
۳) گزارش برای ارسال با ایمیل یا تلگرام
۴) خواندن و آرشیو فایل‌های Markdown

نسخهٔ Pro همهٔ امکانات فعلی را بدون پسرفت نگه می‌دارد و این‌ها را اضافه می‌کند: کتابخانهٔ محلی، ابزارهای هوشمند بدون اینترنت، برند و نامهٔ اداری، و خروجی‌های تازه.

## ۲. تصمیم‌های اصلی

| موضوع | تصمیم |
|---|---|
| شکل اجرا | **تک‌فایل + قابل نصب.** خروجی اصلی `MD2Html.html` است که بدون سرور و اینترنت در مرورگر باز می‌شود. نسخهٔ `dist/pwa/` روی https قابل نصب است و از «Open With» پشتیبانی می‌کند. |
| کد منبع | جاوااسکریپت ساده (ES modules) و CSS در چند فایل زیر `src/`. با `esbuild` در یک فایل HTML جمع می‌شود. بدون فریم‌ورک. |
| ذخیره | **کتابخانهٔ محلی در IndexedDB** همان مرورگر. چیزی از دستگاه خارج نمی‌شود. این تصمیم بند «ذخیره‌سازی خودکار خاموش» نسخهٔ اول را لغو می‌کند. |
| هوش مصنوعی | فقط **ابزارهای قاعده‌محور بدون اینترنت.** هیچ API ابری استفاده نمی‌شود. |
| فونت | **وزیرمتن** (OFL، بستهٔ npm `vazirmatn`)، وزن‌های ۴۰۰ و ۷۰۰. با `pyftsubset` به حروف فارسی و عربی، لاتین پایه، ارقام و علائم کوچک می‌شود و به‌صورت base64 در فایل جاسازی می‌شود. فونت‌های سیستم fallback هستند. |
| کتابخانه‌های بیرونی | فقط از npm و در زمان build بسته‌بندی می‌شوند، همه با مجوز MIT یا OFL: `esbuild` (dev)، `fflate` (zip)، `qrcode-generator` (QR)، `modern-screenshot` (تصویر). هیچ درخواست شبکه‌ای در زمان اجرا مجاز نیست. |
| سقف حجم | `dist/MD2Html.html` حداکثر **۹۰۰ کیلوبایت** با احتساب فونت. |

## ۳. ساختار پروژه

```
MD2Html/
  package.json            # اسکریپت‌ها: build، test، dev
  build.mjs               # bundle + inline CSS/JS/font → dist/MD2Html.html و dist/pwa/
  src/
    index.html            # اسکلت رابط با جای‌نگه‌دار <!--CSS--> و <!--JS-->
    styles/               # tokens.css، layout.css، components.css، document.css، print.css، reading.css، present.css
    fonts/                # فونت‌های subset‌شده (woff2)
    js/
      app.js              # فقط سیم‌کشی ماژول‌ها
      core/               # store.js (state + رویدادها)، dom.js، notify.js، history.js (undo/redo)
      content/            # markdown.js، sanitize.js، highlight.js، cleanup.js، persian.js، chart.js، toc.js، analytics.js، detect.js
      editor/             # preview.js، source.js، toolbar.js، paste.js، images.js
      library/            # db.js (IndexedDB)، library-ui.js، versions.js
      brand/              # brands.js، letter.js، jalali.js، qr.js، watermark.js
      export/             # html.js، interactive.js، email.js، print.js، markdown.js، png.js، docx.js، present.js
      ui/                 # palette.js (⌘K)، shortcuts.js، settings.js، theme.js، reading.js، modal.js
      pwa/                # register.js (فقط روی http/https)
  pwa/                    # manifest.webmanifest، sw.js، icons/ (192 و 512 PNG + SVG)
  tests/                  # *.test.mjs با node:test برای ماژول‌های خالص
  dist/                   # خروجی build (در git ثبت می‌شود)
  MD2Html.html            # کپی dist/MD2Html.html؛ همان فایلی که مجتبی باز می‌کند
```

قواعد مرز ماژول‌ها:
- ماژول‌های `content/`، `brand/jalali.js`، `brand/qr.js` و `export/docx.js` (بخش تولید XML) **خالص** هستند: به DOM سراسری یا state دست نمی‌زنند و با `node --test` تست می‌شوند. هرجا DOM لازم است، از ورودی پارامتر یا `DOMParser` تزریقی استفاده می‌کنند.
- فقط `core/store.js` state نگه می‌دارد. بقیه از طریق `store.get/set/on` با آن کار می‌کنند.
- هیچ فایلی بیش از حدود ۴۰۰ خط نشود. اگر شد، تقسیم شود.

## ۴. مدل داده

```js
Document = {
  id, title, subtitle, source /* متن خام md یا html */, sourceType: 'md'|'html'|'text',
  html /* HTML پاک‌سازی‌شدهٔ پیش‌نمایش ویرایش‌شده */, mode: 'doc'|'web'|'letter',
  brandId, watermark: {preset:'none'|'draft'|'confidential'|'final'|'copy'|'custom', text},
  letter: {number, date /* شمسی yyyy/mm/dd */, attachments, recipient, subject, greeting:boolean, signer:{name, role}},
  tags: [], pinned: false, createdAt, updatedAt, layout: {...تنظیمات صفحهٔ فعلی: theme، font، margin، header/footer...}
}
Version  = { id, docId, savedAt, reason: 'auto'|'manual'|'before-cleanup'|'before-import', title, source, html }
Brand    = { id, name, theme, colors:{primary, accent}, mastheadText, mastheadImage /* dataURL */, footerText, footerImage,
             signatureImage, stampImage, signer:{name, role}, letterPrefix, letterCounter, website, qr:{enabled, kind:'url'|'tel'|'text', value, position} }
```

ذخیره در IndexedDB با پایگاه `md2html` و سه store به نام‌های `documents`، `versions` و `brands`. تنظیمات در store جدای `settings` نگه داشته می‌شود.

## ۵. امکانات به تفکیک مرحله

هر مرحله یک نسخهٔ کامل و قابل استفاده تحویل می‌دهد. بعد از هر مرحله، `MD2Html.html` ریشه به‌روز می‌شود.

### مرحلهٔ ۱ — پایه

1. **ساختار و build:** ساختار بالا، با `npm run build` که `dist/MD2Html.html` و کپی ریشه را می‌سازد.
2. **انتقال کامل امکانات فعلی (بدون پسرفت):** فهرست مرجع از روی کد `1file-old/MD2Html.html` استخراج و در `docs/superpowers/plans/feature-inventory.md` ثبت می‌شود. حداقل این‌ها را شامل می‌شود:
   - ورود فایل با انتخاب، کشیدن و رها کردن، و **Paste فایل** (ناحیهٔ چسباندن و ⌘V در جای خالی)
   - Markdown و HTML و متن ساده، و حالت وب عریض برای HTML پیست‌شده
   - ویرایش دیداری با undo/redo و قالب‌بندی انتخاب
   - سربرگ و پاورقی متنی و تصویری با تراز، عرض، ارتفاع و تکرار در چاپ
   - چهار قالب رنگی، اندازهٔ قلم و حاشیه
   - افزودن تیتر، کارت، نقل‌قول، جداکننده، تصویر و دکمهٔ لینک
   - چسباندن تصویر و آپلود zi2
   - تحلیل محتوا
   - خروجی HTML، Markdown، PDF و ایمیل با Save As
   - تنظیمات JSON: وارد کردن v1 و v2 و صدور v3
3. **ظاهر تازه:** همان هویت سبز-خاکستری، مدرن‌تر. حالت تیره و روشن برای خودِ برنامه. هدر شامل عنوان سند، برند فعال، دکمهٔ کتابخانه، راهنمای ⌘K و منوی خروجی است. چیدمان سه‌ستونه در دسکتاپ و پشته‌ای در موبایل.
4. **کتابخانهٔ محلی:**
   - ذخیرهٔ خودکار با تأخیر ۱٫۵ ثانیه
   - کشوی کتابخانه با جست‌وجو در عنوان و متن، فیلتر برچسب، سنجاق و مرتب‌سازی
   - تکثیر سند و حذف با «برگردان» ۸ ثانیه‌ای
   - **نسخه‌ها:** خودکار هر ۵ دقیقه تغییر، دستی با ⌘S، و پیش از پاک‌سازی یا وارد کردن. سقف ۳۰ نسخه برای هر سند. نمایش و بازگردانی نسخه.
   - **پشتیبان کامل:** صدور و ورود JSON همهٔ سندها، نسخه‌ها، برندها و تنظیمات
   - کلید «ذخیرهٔ خودکار» در تنظیمات
   - با دست کاری قدیمی‌ترین نسخه‌های خودکار حذف می‌شوند تا جا آزاد شود. اگر سهمیهٔ ذخیره پر شد، پیام فارسی نشان داده می‌شود.
5. **پالت فرمان ⌘K / Ctrl+K:** جست‌وجوی فازی فارسی و انگلیسی در همهٔ فرمان‌ها، سندهای کتابخانه و برندها. هر فرمان میان‌بر خودش را نشان می‌دهد. ماژول‌های بعدی فرمانشان را از طریق `palette.register({id, title, keywords, shortcut, run})` اضافه می‌کنند.
6. **PWA:** `manifest.webmanifest` (fa، rtl)، `sw.js` با cache-first و نسخه‌دار، `file_handlers` برای ‎.md/.markdown/.txt/.html/.htm و مصرف‌کنندهٔ `launchQueue`. ثبت service worker فقط روی http یا https انجام می‌شود و روی `file://` بی‌صدا رد می‌شود.

### مرحلهٔ ۲ — محتوا و ابزار هوشمند

1. **پاک‌سازی یک‌کلیکهٔ خروجی AI** (`content/cleanup.js`):
   - هر قاعده جدا روشن یا خاموش می‌شود.
   - قبل از اعمال، فهرست تغییرها با تعداد و نمونهٔ قبل/بعد نشان داده می‌شود.
   - پیش از اعمال یک نسخه ذخیره می‌شود و با undo برمی‌گردد.
   - بلوک کد، کد درون‌خطی، URL و ایمیل هرگز تغییر نمی‌کنند.
   - قاعده‌ها:
     - ی و ک عربی (ي ك) ← فارسی
     - نیم‌فاصله: «می »/«نمی » پیشوندی، و «ها/های/تر/ترین/ام/ات/اش» پسوندی که با فاصله جدا شده‌اند. فهرست استثنا در تست‌ها هست.
     - ارقام لاتین ← فارسی، فقط داخل جملهٔ فارسی (پیش‌فرض: روشن)
     - علائم فارسی: ، ؛ ؟ و «» در جملهٔ فارسی، و حذف فاصلهٔ پیش از علامت
     - حذف ایموجی تزئینی در ابتدای تیتر و آیتم فهرست (پیش‌فرض: روشن). حذف همهٔ ایموجی‌ها (پیش‌فرض: خاموش).
     - حذف جمله‌های اضافهٔ AI، فقط اگر یک پاراگراف کامل در ابتدا یا انتهای سند باشند. فهرست فارسی و انگلیسی، مثل «امیدوارم مفید باشد»، «اگر سؤال دیگری داشتید…»، «حتماً!»، “Certainly!”، “I hope this helps”.
     - مصنوعات Markdown: `**` یتیم، خط‌های خالی بیش از دو، فاصلهٔ انتهای خط، جداکنندهٔ تکراری
2. **تشخیص نوع سند** (`content/detect.js`): بعد از ورود متن، یک نوار پیشنهاد کوچک و قابل بستن نشان داده می‌شود.
   - اگر نشانهٔ خروجی AI دید: «به نظر خروجی هوش مصنوعی است — پاک‌سازی؟»
   - اگر نشانهٔ نامه دید («باسمه تعالی»، «به:» یا «موضوع:» در ابتدا): پیشنهاد حالت نامه
3. **بلوک‌های غنی:**
   - کد fenced با رنگ‌آمیزی سبک خودساخته (js/ts، python، html/xml، css، json، bash، sql)، برچسب زبان، جهت LTR و دکمهٔ کپی. دکمهٔ کپی فقط در رابط است و در چاپ و خروجی ساده نمی‌آید.
   - چک‌لیست `- [ ]` و `- [x]` که در پیش‌نمایش با کلیک تیک می‌خورد و در منبع هم به‌روز می‌شود.
   - کادرهای `> [!NOTE|TIP|IMPORTANT|WARNING|CAUTION]` با نام‌های فارسی معادل `[!نکته]`، `[!راهنما]`، `[!مهم]`، `[!هشدار]` و `[!خطر]`.
   - **نمودار از جدول:** روی جدولی که ستون اول برچسب و دست‌کم یک ستون عددی دارد، دکمهٔ «نمودار» ظاهر می‌شود. ارقام فارسی و جداکنندهٔ هزارگان هم پذیرفته می‌شوند. نمودار SVG میله‌ای، خطی یا دایره‌ای با رنگ‌های قالب، بعد از جدول درج می‌شود. محور x نمودار میله‌ای و خطی **چپ‌به‌راست** است.
4. **فهرست مطالب و حالت مطالعه:**
   - تب فهرست در پنل کناری، ساخته‌شده از h1 تا h3، با پیمایش به هر بخش و برجسته کردن بخش فعلی
   - فرمان «درج فهرست مطالب در سند»
   - حالت مطالعهٔ تمام‌صفحه با زمان تقریبی مطالعه، نوار پیشرفت (**پر شدن از چپ به راست**)، بزرگ و کوچک کردن قلم، و زمینهٔ روشن، کرم یا تیره. خروج با Esc.

### مرحلهٔ ۳ — نامه و برند

1. **مدیریت برندها:**
   - ساختن، ویرایش، حذف و تکثیر برند
   - یک برند نمونه («مجتمع کامپیوتر یک دو سه»، فقط متنی، با وب‌سایت computer123.ir) در اولین اجرا ساخته می‌شود.
   - تعویض برند از هدر و ⌘K. برند روی رنگ، سربرگ، پاورقی، امضا، مهر و QR اعمال می‌شود.
2. **حالت نامهٔ اداری:**
   - بلوک بالای نامه شامل تاریخ شمسی (پیش‌فرض امروز، قابل ویرایش)، شماره و پیوست
   - گیرنده («به:»)، موضوع، و «با سلام و احترام» اختیاری
   - بلوک امضا در پایان با نام و سمت. تصویر امضا و مهر روی هم قرار می‌گیرند و جابه‌جا می‌شوند.
   - «شماره بگیر» عددی به شکل `پیشوند/شمارنده` می‌سازد و شمارندهٔ برند را یکی بالا می‌برد.
   - `brand/jalali.js` خودساخته است و تست دارد: تبدیل دوطرفه، و قالب ارقام فارسی و لاتین.
3. **واترمارک:** حالت‌های پیش‌نویس، محرمانه، نهایی، رونوشت و متن دلخواه. مورب و کم‌رنگ است و در پیش‌نمایش، چاپ، PNG و HTML دیده می‌شود. در Word ساخته نمی‌شود و این محدودیت در رابط گفته می‌شود.
4. **QR کد:** با `qrcode-generator` به‌صورت SVG ساخته می‌شود. محتوا می‌تواند وب‌سایت برند، تلفن یا متن یا لینک دلخواه باشد. جای آن گوشهٔ پاورقی یا کنار بلوک نامه است و اندازه‌اش قابل تنظیم است.

### مرحلهٔ ۴ — خروجی‌ها

1. **تصویر برای تلگرام** (`export/png.js` با `modern-screenshot`):
   - حالت «صفحه‌ای» به نسبت A4 در عرض ۱۲۴۰ پیکسل؛ صفحه‌بندی در مرز بلوک‌ها
   - حالت «تصویر بلند» یک‌تکه
   - چند صفحه در یک ZIP (با `fflate`) ذخیره می‌شود. یک صفحه را می‌شود مستقیم **در کلیپ‌بورد کپی کرد** تا در تلگرام دسکتاپ Paste شود.
   - فونت جاسازی‌شده در تصویر درست دیده می‌شود.
2. **Word (.docx واقعی)** (`export/docx.js` + `fflate`):
   - پاراگراف‌ها RTL و bidi
   - تیترها با استایل Heading، تأکید پررنگ و مورب، فهرست‌های ساده
   - جدول با سطر سرصفحهٔ تکرارشونده
   - تصویر جاسازی‌شده (PNG و JPEG، و تبدیل WebP و GIF به PNG با canvas)
   - لینک
   - سربرگ و پاورقی متنی و تصویری برند
   - فونت `Vazirmatn` با fallback `Tahoma`
   - کد با فونت monospace و جهت LTR
   - تست: فایل زیپ باز می‌شود و XMLهایش well-formed هستند.
3. **حالت ارائه:**
   - سند در h1، h2 و `---` به اسلاید تمام‌صفحه شکسته می‌شود، با رنگ برند.
   - کلیدها: **→ و Space برای بعدی، ← برای قبلی** (فلش‌ها mirror نمی‌شوند). گروه دکمه‌ها `direction:ltr` است.
   - شمارندهٔ اسلاید و نوار پیشرفت (از چپ به راست)
   - خروجی ارائه به‌صورت یک HTML مستقل
4. **HTML تعاملی:**
   - شامل فهرست مطالب شناور (کشویی در موبایل)، حالت تاریک، دکمه‌های بزرگ و کوچک کردن قلم، نوار پیشرفت مطالعه (از چپ به راست)، چک‌لیست قابل تیک، دکمهٔ کپی کد و «بازگشت به بالا»
   - JS درون‌خطی کوچک دارد و کد ویرایشگر را ندارد.
   - خروجی «HTML ساده» فعلی هم می‌ماند.

## ۶. قواعد رابط (ثابت در همهٔ مراحل)

- کل رابط فارسی و RTL است. فقط کد و نام فایل لاتین می‌مانند.
- **سه چیز هرگز mirror نمی‌شوند:**
  - کنترل‌های قبلی/بعدی (چپ = قبلی، راست = بعدی)
  - پروگرس‌بار، اسلایدر و محور افقی نمودار (پر شدن از چپ)
  - فلش‌های ماه در تقویم
- هیچ `alert`، `confirm` یا `prompt` جدیدی اضافه نمی‌شود. تأییدها با modal داخلی یا toast دارای «برگردان» انجام می‌شوند. موارد قدیمی هنگام انتقال جایگزین می‌شوند.
- دسترس‌پذیری: برچسب برای همهٔ دکمه‌های آیکونی، پیمایش با کیبورد، trap فوکوس در modal و پالت، و `prefers-reduced-motion`.
- همهٔ HTML ورودی از `content/sanitize.js` رد می‌شود و URLها فقط `https:`، `http:`، `mailto:`، `tel:` و `data:image/*` (فقط برای تصویر) هستند.

## ۷. خطاها

پیام همهٔ خطاها فارسی و مشخص است: فایل نامعتبر یا بزرگ‌تر از ۵ مگابایت، تصویر بیش از ۸ مگابایت، پر شدن سهمیهٔ ذخیره، شکست ساخت تصویر یا Word، و نبودن Clipboard. خطای یک خروجی نباید state سند را خراب کند.

## ۸. تست و پذیرش

- **واحد** (`npm test` با `node --test`): markdown (شامل چک‌لیست، کادر و کد)، sanitize، cleanup (هر قاعده با نمونهٔ مثبت و منفی و استثنا)، persian، jalali، چارت (استخراج دادهٔ جدول)، اعتبارسنجی تنظیمات v1/v2/v3، و ساختار docx.
- **دود (Smoke) در مرورگر** با Playwright MCP بعد از هر مرحله: باز کردن `MD2Html.html`، ورود md و html، ویرایش و undo، ذخیره در کتابخانه و بازکردن پس از تازه‌سازی، ⌘K، و خروجی‌های همان مرحله. کنسول بدون خطا و **بدون درخواست شبکه** باشد.
- **پذیرش هر مرحله:** همهٔ تست‌ها سبز، build زیر سقف حجم، فهرست امکانات مرحلهٔ ۱ بدون پسرفت، و چک‌لیست RTL («فلش بعدی راست است؟ پروگرس از چپ پر می‌شود؟»).

## ۹. خارج از محدوده

سرور، حساب کاربری، همگام‌سازی ابری، API هوش مصنوعی، همکاری هم‌زمان، Mermaid و فرمول ریاضی، Share Target موبایل، و همگام‌سازی دوطرفهٔ کامل منبع و پیش‌نمایش (جز تیک چک‌لیست).
