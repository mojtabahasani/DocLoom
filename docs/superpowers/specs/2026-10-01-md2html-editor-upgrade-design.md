# طرح ارتقای ویرایشگر MD2Html

**تاریخ:** ۱ اکتبر ۲۰۲۶  
**وضعیت:** پیش‌نویس برای بازبینی کاربر  
**محدوده:** ارتقای فایل مستقل `MD2Html.html` و اتصال اختیاری آپلود تصویر به API پروژهٔ `xi2-php` روی `zi2.ir`.

## هدف

MD2Html از مبدل متن به یک ویرایشگر سند فارسی و آمادهٔ چاپ تبدیل شود، درحالی‌که همچنان بدون نصب و بدون سرور برای ویرایش و خروجی‌گیری کار کند. آپلود تصویر فقط هنگام انتخاب کاربر و از طریق API هاست انجام می‌شود.

## رویکرد

فایل مستقل HTML حفظ می‌شود و کد داخل همان فایل به بخش‌های روشن برای ویرایشگر، مدیریت رسانه، صفحه‌آرایی و خروجی تقسیم می‌شود. این گزینه، آفلاین‌بودن پایه و سهولت انتقال فایل را نگه می‌دارد. قابلیت آپلود به شبکه و API هاست نیاز دارد و به‌صورت اختیاری عمل می‌کند.

## تجربهٔ ویرایش

- پنل ابزار سمت راست و پنل تنظیمات سمت چپ در قاب برنامه ثابت می‌مانند؛ پیمایش سند فقط در ناحیهٔ مرکزی انجام می‌شود.
- برای جا دادن ابزارها در ارتفاع صفحه، پنل‌ها از گروه‌بندی و بخش‌های بازوبسته‌شونده استفاده می‌کنند و خود سند مرکز تنها ناحیهٔ پیمایش اصلی خواهد بود.
- انتخاب متن، نوار ابزار شناور زمینه‌ای را نشان می‌دهد: راست‌چین، وسط‌چین، چپ‌چین، بولد، تغییر اندازه، رنگ متن، رنگ پس‌زمینه، هایلایت‌های آماده و پاک‌کردن قالب‌بندی.
- عملیات ویرایش و قالب‌بندی با Undo و Redo قابل بازگشت‌اند. میانبرهای رایج صفحه‌کلید نیز پشتیبانی می‌شوند.
- تصویر قابل درج در محل نشانگر است و پس از درج می‌توان اندازه و تراز آن را تنظیم کرد.
- حالت «سورس HTML» کد HTML سند خروجی را در ویرایشگر کد نشان می‌دهد؛ کاربر می‌تواند فایل `.html` را باز کند، سورس را ویرایش کند و نتیجه را به پیش‌نمایش برگرداند. ویرایش سورس به محتوای سند محدود است؛ CSS و JavaScript برنامه اجرا یا جایگزین نمی‌شوند.

## چسباندن محتوا و تصاویر

- چسباندن متن ساده، متن ساده وارد می‌کند.
- اگر Clipboard دارای HTML باشد، ساختار و قالب‌بندی متداول، فهرست‌ها، جدول‌ها، لینک‌ها و استایل‌های ظاهری مجاز حفظ می‌شوند.
- سورس HTML و فایل‌های `.html` از طریق DOM parser خوانده می‌شوند؛ محتوای `body` وارد سند می‌شود و از همان پاک‌سازی امن Clipboard عبور می‌کند. برای اعمال سورس، کنترل صریح «اعمال به پیش‌نمایش» در دسترس است.
- HTML ورودی از فهرست مجاز عناصر و ویژگی‌ها عبور می‌کند. اسکریپت، event handler، iframe، فرم، محتوای اجرایی و URLهای ناامن حذف می‌شوند؛ حفظ قالب‌بندی به معنی اجرای عین کد صفحهٔ مبدأ نیست.
- لینک‌های http/https و mailto حفظ می‌شوند. تصویرهای دارای دادهٔ تصویری در Clipboard جاسازی می‌شوند؛ تصاویر دارای URL خارجی، به شکل URL باقی می‌مانند و برای نمایش به اینترنت نیاز دارند.
- تصویر کپی‌شده با Clipboard API وارد متن، فیلد تصویر سربرگ یا فیلد تصویر پاورقی می‌شود. انتخاب فایل نیز مسیر جایگزین است.
- اندازه و نوع تصویر پیش از آپلود کنترل می‌شوند و پیام خطای خوانا برای قطع اتصال، پاسخ نامعتبر، رد فایل و محدودیت سرور نمایش داده می‌شود.

## سربرگ و پاورقی

- سربرگ و پاورقی هر کدام فیلد متن و تصویر، انتخاب تصویر از Clipboard یا فایل، حذف تصویر، تراز و اندازهٔ مستقل دارند.
- تراز تصویر شامل کشیده در عرض، وسط، راست و چپ است. متن سربرگ و پاورقی نیز جایگاه و تراز مستقلی دارد.
- گزینهٔ تکرار سربرگ و پاورقی در صفحه‌های چاپ A4 با سازوکار چاپ مرورگر تنظیم می‌شود؛ متن و تصویر باید در محدودهٔ حاشیهٔ چاپ بمانند.
- گزینه‌های نمایش عنوان/زیرعنوان، سربرگ و پاورقی مستقل‌اند. خاموش‌کردن هر گزینه، محتوای اصلی سند را دست‌نخورده نگه می‌دارد.
- تنظیم اندازهٔ صفحه، حاشیه و تکرار در پیش‌نمایش و خروجی چاپ یکسان اعمال می‌شود.

## تحلیل محتوا

پنل تحلیل به‌صورت زنده تعداد سطر، نویسه با و بدون فاصله، واژه، حجم تقریبی متن، لینک، تصویر، جدول و تیتر را نشان می‌دهد. حجم HTML تخمینی است و به‌عنوان حجم دقیق فایل خروجی معرفی نمی‌شود.

## رسانه و API آپلود `zi2.ir`

سه روش درج تصویر در دسترس است:

1. جاسازی تصویر داخل سند برای فایل کاملاً مستقل و قابل‌استفادهٔ آفلاین.
2. درج نشانی خارجی که کاربر ارائه می‌دهد.
3. آپلود اختیاری تصویر به API خود کاربر در `zi2.ir` و درج URL برگشتی در سند.

اتصال آپلود از طریق `fetch` و `multipart/form-data` انجام می‌شود. فایل HTML هیچ کلید سرویس ثالثی در خود نگه نمی‌دارد. مسیر پیشنهادی `https://zi2.ir/api/upload/upload.php` از rewrite موجود در `.htaccess` محلی به‌دست آمده و در تنظیمات قابل‌تغییر است؛ کارکرد آن روی هاست باید تأیید شود. نام فیلد فایل در نسخهٔ PHP بررسی‌شده `file` است؛ پاسخ موفق در کد بررسی‌شده در `data.upload.fileUrl` قرار دارد. پیاده‌سازی باید خطاهای HTTP و JSON را کنترل کند.

API فعلی پروژه امکان آپلود مهمان را با تنظیم سرور دارد و پیکربندی نمونه CORS عمومی (`*`) می‌فرستد. به همین دلیل:

- آپلود فقط با اقدام صریح کاربر انجام می‌شود و پیش از ارسال، مقصد و پیامد ساخت لینک عمومی نمایش داده می‌شود.
- اعتبارسنجی سمت PHP مرجع نهایی است؛ رابط کاربری فقط برای تجربهٔ بهتر بررسی نوع/اندازه دارد.
- تنظیمات سمت سرور باید حجم و نوع واقعی فایل را محدود کند؛ درخواست‌ها باید از نظر تعداد/مصرف قابل‌کنترل باشند تا مسیر مهمان به نقطهٔ مصرف بی‌رویه تبدیل نشود.
- در صورت پشتیبانی، CORS به مبداهای لازم محدود می‌شود. چون فایل مستقل ممکن است با مبدا `null` باز شود، روش اجرای فایل و سیاست CORS باید در مرحلهٔ اتصال با هاست بررسی شود.
- کلید API یا رمز کاربری در فایل HTML قرار نمی‌گیرد. در صورت نیاز آینده به آپلود احراز هویت‌شده، توکن از سازوکار جداگانه و امن تأمین می‌شود.
- لینک مستقیم برای نمایش و چاپ سند استفاده می‌شود؛ لینک کوتاه اشتراک‌گذاری فقط در صورت سازگاری با پاسخ API و قابل‌استفاده‌بودن به‌عنوان `img src` انتخاب خواهد شد.

## ذخیره و خروجی

- خروجی HTML و Markdown نام پیشنهادی می‌گیرد و امکان تغییر نام پیش از ذخیره دارد.
- در مرورگرهایی که ذخیره‌سازی مستقیم با انتخاب‌گر فایل را پشتیبانی می‌کنند، پنجرهٔ Save As برای انتخاب نام و مسیر باز می‌شود. در مرورگرهای دیگر، دانلود معمول مرورگر با نام انتخاب‌شده جایگزین می‌شود.
- PDF از مسیر چاپ مرورگر صادر می‌شود؛ کاربر در پنجرهٔ چاپ سیستم، چاپگر یا Save as PDF و مسیر را انتخاب می‌کند.
- خروجی HTML شامل استایل چاپ، محتوای امن‌شده، URL تصویرهای خارجی یا داده‌های تصویری جاسازی‌شده و تنظیمات سربرگ/پاورقی است.
- خروجی Markdown شامل محتوای سند، لینک‌ها و نشانی تصویرهاست. قالب‌بندی پیچیده‌ای که Markdown بیان نمی‌کند، در فایل Markdown قابل حفظ کامل نیست.

## معماری و جریان داده

1. فایل Markdown، HTML یا متن وارد می‌شود و به DOM امن تبدیل می‌شود.
2. کاربر در پیش‌نمایش ویرایش می‌کند؛ تاریخچهٔ Undo/Redo تغییرهای قابل‌بازگشت را نگه می‌دارد.
3. در چسباندن HTML، پاک‌سازی و تبدیل مجاز انجام می‌شود؛ در چسباندن تصویر، کاربر مقصد درج را تعیین می‌کند.
4. تصویر بر اساس انتخاب کاربر جاسازی، با URL درج، یا به API تنظیم‌شده ارسال می‌شود.
5. تنظیمات صفحه‌آرایی و اجزای صفحه روی پیش‌نمایش و خروجی اعمال می‌شوند.
6. تحلیل محتوا از DOM جاری محاسبه می‌شود.
7. خروجی HTML/Markdown با انتخاب محل ذخیره و PDF از پنجرهٔ چاپ ساخته می‌شود.

حالت سورس HTML از خروجی HTML مستقل ساخته می‌شود. اعمال سورس، فقط بدنهٔ محتوا را از HTML ورودی استخراج و پاک‌سازی می‌کند؛ عناصر اجرایی، stylesheetهای صفحهٔ مبدأ و سرصفحه‌های سند واردشده اجرا نمی‌شوند. سپس خروجی HTML برنامه با قالب‌بندی داخلی MD2Html دوباره ساخته می‌شود.

بخش‌های منطقی داخل فایل: `Editor`, `SelectionToolbar`, `History`, `ClipboardImporter`, `MediaManager`, `PageFurniture`, `DocumentAnalytics`, `ExportManager` و `Settings`. این نام‌ها مرزبندی مسئولیت‌اند و الزاماً فایل جدا ایجاد نمی‌کنند.

## محدودیت‌ها و خطاها

- مرورگرهای مختلف مجوز Clipboard، انتخاب‌گر ذخیره و چاپ را متفاوت پشتیبانی می‌کنند؛ برای Clipboard و Save As مسیر جایگزین ارائه می‌شود.
- PDF از API چاپ مرورگر تولید می‌شود و پشتیبانی دقیق از سربرگ/پاورقی ممکن است میان مرورگرها متفاوت باشد؛ پیش‌نمایش چاپ باید معیار بررسی چیدمان باشد.
- تصویر خارجی یا آپلودشده هنگام آفلاین‌بودن نمایش داده نمی‌شود. فایل خروجیِ دارای URL خارجی برای نمایش تصویر به شبکه وابسته است.
- API آپلود در صورت CORS، مسیر اشتباه، محدودیت هاست یا پاسخ ناسازگار باید خطا را در رابط اعلام کند؛ سند اصلی و تصویر جاسازی‌شده نباید از بین بروند.
- آپلود موفق یک اثر خارجی و عمومی ایجاد می‌کند؛ حذف آن نیازمند API حذف و دسترسی مناسب است و در این مرحله حذف خودکار فرض نمی‌شود.

## گام‌های پیاده‌سازی

1. تثبیت قاب ثابت و ویرایشگر مرکزی، قالب‌بندی انتخاب و تاریخچه.
2. واردکنندهٔ Clipboard امن برای HTML و تصویر و مدیریت سربرگ/پاورقی.
3. API آپلود قابل‌تنظیم `zi2.ir` و درج URL برگشتی.
4. تحلیل زنده، Save As و هماهنگ‌سازی خروجی HTML/Markdown/PDF.
5. بررسی دستی چسباندن نمونه‌ها، تاریخچه، تصاویر، چندصفحه‌ای A4 و مسیرهای خروجی در مرورگر هدف.

## مواردی که پیش از اتصال واقعی باید از نسخهٔ مستقر تأیید شوند

- نشانی دقیق API آپلود روی `zi2.ir`؛ ساختارهای محلی در مخزن چند snapshot دارد و مستندات و کد در نام فیلد آپلود کاملاً همسان نیستند.
- پشتیبانی هاست از CORS برای فایل محلی با مبدا `null` یا نیاز به میزبانی MD2Html از یک URL ثابت.
- محدودیت واقعی حجم و فعال‌بودن آپلود مهمان در تنظیمات هاست.

این مقادیر در رابط به‌صورت تنظیمات اتصال در نظر گرفته می‌شوند و نشانی محیط تولید تا زمان تأیید از روی ساختار لوکال حدس زده نمی‌شود.
