# راه‌اندازی آپلود تصویر DataSave روی zi2.ir

DataSave می‌تواند تصویر را از مرورگر با `multipart/form-data` به API پروژهٔ zi2 بفرستد. فیلد «نشانی API آپلود zi2.ir» با مسیر پیشنهادی `https://zi2.ir/api/v1/upload.php` شروع می‌شود؛ این مسیر از rewrite موجود در `.htaccess` محلی استخراج شده و در صورت تفاوت نسخهٔ هاست قابل‌تغییر است.

## تنظیم در برنامه

۱. مسیر دقیق endpoint آپلود را از نسخهٔ مستقر پروژه بردارید؛ فایل محلی بررسی‌شده در snapshot پروژه در `src/api/upload/upload.php` قرار دارد. فایل `.htaccess` پوشهٔ `public` مسیر `/api/...` را به `/src/api/...` بازنویسی می‌کند و راهنما نیز `/api/upload/upload.php` را به‌کار می‌برد. این ساختار محلی مسیر نصب روی هاست را تضمین نمی‌کند؛ URL واقعی را وارد کنید.
۲. در DataSave تصویر را انتخاب کنید تا برای آپلود آماده شود.
۳. URL را در فیلد endpoint وارد کنید و دکمهٔ «آپلود تصویر انتخاب‌شده به zi2.ir» را بزنید.
۴. پس از تأیید پیام عمومی‌بودن فایل، DataSave فایل را با فیلد `file` می‌فرستد.

پاسخ سازگار با handler محلی بررسی‌شده، ساختاری مانند این دارد:

```json
{
  "success": true,
  "data": {
    "upload": {
      "fileUrl": "https://zi2.ir/storage/uploads/.../image.jpg",
      "shareUrl": "https://zi2.ir/view/abc123"
    }
  }
}
```

DataSave لینک مستقیم `data.upload.fileUrl` را برای `img src` استفاده می‌کند و اگر مقدار برگشتی مسیر API را هم در ابتدای مسیر فایل داشته باشد، آن مسیر را اصلاح می‌کند. لینک `shareUrl` صفحهٔ نمایش است و جایگزین نشانی مستقیم تصویر نیست. handler محلی `fileUrl` را با حذف مسیر `/src/api/upload/upload.php` از `REQUEST_URI` می‌سازد؛ هنگام استفاده از مسیر بازنویسی‌شدهٔ `/api/upload/upload.php` این مقدار ممکن است مسیر نادرست بسازد. پاسخ واقعی روی هاست را بررسی کنید و در صورت نیاز handler را در پروژهٔ PHP اصلاح کنید.

## کنترل‌های هاست

- فعال‌بودن آپلود مهمان را در تنظیمات سرویس تأیید کنید؛ در handler محلی این گزینه با `enable_guest_upload` کنترل می‌شود.
- `upload_max_filesize` و `post_max_size` در PHP و محدودیت API را با اندازهٔ مجاز تصویر هماهنگ کنید.
- API باید فقط تصویرهای مجاز را با بررسی محتوای واقعی فایل بپذیرد و پاسخ JSON و HTTP status درست بدهد.
- API محلی CORS عمومی (`Access-Control-Allow-Origin: *`) دارد. اگر سیاست هاست متفاوت است، مبدا اجرای برنامه باید مجاز باشد. فایل `file://` معمولاً با Origin برابر `null` درخواست می‌فرستد؛ اگر هاست آن را نمی‌پذیرد، DataSave را از یک origin HTTPS مجاز باز کنید یا CORS را فقط برای origin مشخص خودتان تنظیم کنید.
- چون آپلود مهمان می‌تواند عمومی و بدون ورود باشد، محدودیت نرخ/حجم و پایش مصرف روی سرور توصیه می‌شود.
- هیچ توکن یا گذرواژه‌ای در فایل تنظیمات JSON نمونه ذخیره نمی‌شود.

اگر آپلود خطا داد، ابتدا URL endpoint، پاسخ HTTP، فعال‌بودن آپلود مهمان، محدودیت PHP و CORS را بررسی کنید. تصویر محلی در DataSave باقی می‌ماند و با شکست آپلود از سند حذف نمی‌شود.

## به‌روزرسانی ۹ آبان ۱۴۰۵
- نشانی قبلی `/api/upload/upload.php` روی هاست 404 می‌دهد. API فعال `https://zi2.ir/api/v1/upload.php` است: فیلد `image` و پاسخ `{success, file:{id, path}}`. نشانی تصویر برابر است با `https://zi2.ir/` + `file.path`. تنظیم قدیمی خودکار به نشانی تازه منتقل می‌شود.
- این API هدر CORS ندارد. وقتی برنامه از سرور DataSave (`http://localhost:7123` یا نشانی شبکه) باز باشد، آپلود از مسیر `/api/upload` سرور فرستاده می‌شود. این مسیر فقط به هاست‌های مجاز (zi2.ir) و فقط با HTTPS آپلود می‌کند. در نسخهٔ تک‌فایل (`file://`) آپلود مستقیم ممکن نیست؛ مگر اینکه CORS روی هاست zi2 فعال شود.
